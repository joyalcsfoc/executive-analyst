# Genie Ontology preparation checklist (Step 6)

Genie Ontology is a **learned** context graph (gated preview). Do **not** install it as a project artifact. When the workspace turns it on, it should learn from Steps 0–5 plus the ACLs and usage signals below.

## ACLs (as code)

`GRANT SELECT` on the five metric views and ten tagged dims runs in the `grant_metric_views` task of `apply_metric_views` ([`../metric_views/grant_metric_views.sql`](../metric_views/grant_metric_views.sql)). Principal = bundle var `genie_space_permission_group` (default `users`).

Verify (replace catalog / group as needed):

```sql
SHOW GRANTS ON VIEW gold_dev.revenue_analytics.metrics_sales_order;
SHOW GRANTS ON VIEW gold_dev.marketing_analytics.metrics_campaign_performance;
SHOW GRANTS ON VIEW gold_dev.manufacturing_analytics.metrics_production_execution;
SHOW GRANTS ON VIEW gold_dev.supply_chain_analytics.metrics_inventory_snapshot;
SHOW GRANTS ON VIEW gold_dev.supply_chain_analytics.metrics_supplier_quality;
SHOW GRANTS ON TABLE gold_dev.dim.dim_plant;
```

Warehouse identity still needs `SELECT` on gold facts/dims, `CREATE VIEW` on domain schemas, and write access on existing `{catalog}.ontology` (see README). Genie space ACL is separate ([`../../resources/executive_analyst.genie_space.yml`](../../resources/executive_analyst.genie_space.yml)).

## UC comments

Measure/field `comment:` values live in `metrics_*.sql` YAML. Spot-check in Catalog Explorer or:

```sql
DESCRIBE TABLE EXTENDED gold_dev.revenue_analytics.metrics_sales_order;
```

## Table Insights / column popularity (manual)

Popularity is **not** produced by a deploy job. Seed query history:

1. `./deploy.sh deploy --target dev` (Genie JSON without the legacy inventory MV).
2. Open the space: `./deploy.sh open --target dev`.
3. Run the 15 questions in [`benchmark_questions.md`](benchmark_questions.md) (and the certified smoke list).
4. In Catalog Explorer → metric view → **Insights**, confirm recent query activity on key columns/measures after usage accumulates.

Encourage real exec use of the same certified bindings so OntoRank prefers metric views + glossary tags over ad-hoc SQL.

## Asset hygiene

Genie data sources list only the five `metrics_*` views plus facts for drill. Do **not** re-add `fact_inventory_snapshot_metric_view` — it competed with `metrics_inventory_snapshot` as a training signal.

## When Genie Ontology preview appears

1. Enable it in the workspace (product UI / account feature flag — not this repo).
2. Confirm it surfaces the five metric views, UC tags (`glossary_terms`, `domain`), and grants for the reader group.
3. Re-run a few benchmark questions; fix **metric views / tags / grants**, not Genie prompt sprawl.
4. No new ontology YAML/OWL required for this step.
